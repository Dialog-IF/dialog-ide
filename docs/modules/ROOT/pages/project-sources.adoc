_The `dialog.json` descriptor: the four source categories, directory vs file entries, ordering, and
the per-format suffix trick._

== dialog.json at a glance

* Lives at the workspace root. Plain JSON (no comments when read; the extension preserves your
  formatting when it edits the file).
* Fields covered here: `name`, `sources`, `binDir`. `exports`, `dialogcOptions`, and `feelies` are
  covered in xref:building-and-exporting.adoc[].

== The four source categories

`sources` is an object with up to four keys. Each is a list of directories and/or files.

[cols="1,3,2",options="header"]
|===
| Category | What it is | When it is compiled / loaded
| `main` | Your story sources — the default category | Always
| `library` | Shared library code, including the Dialog standard library | Always
| `debug` | Sources for use under the interactive debugger | Skein sessions, *Debug in Terminal*, *Run Tests*
| `test` | Unit-test sources | *Run Tests* and `dgbuild test` only — never in a running Skein
|===

* Only `main` is required.
* The "Add File to dialog.json..." picker shows these same one-line descriptions.

== Directory entries vs file entries

* A *directory* entry contributes every `.dg` file that is a *direct child* of that directory
  (not recursive), in *lexical (sorted) order*.
* A *file* entry contributes exactly that one file, wherever you place it in the list.
* Order within a single directory is therefore not something you control precisely — if order
  matters between two files, list them individually in the order you need.
* A missing path is skipped with a log line, not an error.

== Why order matters

* The extension concatenates categories in a fixed order: `main` -> `test` -> `debug` -> `library`.
* Dialog resolves rules *top to bottom*, first match wins. So put *exceptions before default
  rules*, and put files that must override library behavior *before* the library.

== Live source tracking

* *Emphasize:* the IDE watches the project's files continuously. Editing a `.dg` file, *adding* a
  new one, *deleting* one, or renaming — the change is picked up automatically. There is no "refresh
  sources" or "reload project" step.
* A directory entry in `dialog.json` re-expands every time, so a file dropped into (or removed from)
  a `main/` / `debug/` / etc. directory is in (or out of) the next build with no edit to
  `dialog.json`.
* The running Skein always compiles against the *current* files: the next command you send, or the
  next *Replay* / *Replay All*, uses the latest source on disk. You do not need to stop and restart
  the session after a source change.
* The uncovered-source and duplicate-source warnings below re-evaluate live as files and
  `dialog.json` change.

== Per-format source suffixes

* A file named `<name>.<format>.dg` is included *only* when building for that format.
** `colors.zblorb.dg` — only in a `.zblorb` export.
** `layout.dgdebug.dg` — only when running against `dgdebug` (Skein session, *Debug in Terminal*,
   *Run Tests*).
** Recognized suffixes: `zblorb`, `z8`, `aa`, `dgdebug`.
* A file with no suffix, or a suffix that matches no format the IDE builds for, is always included.
* Use this to tune colors / layout / debug helpers per target without leaking them into other
  builds.

== Uncovered-source warning

* Create a `.dg` file that no category covers and the extension flags it: a dismissible
  notification *and* a persistent Explorer badge, both with a one-click *"Add to dialog.json"* fix.
* Toggle with the `dialog-ide.warnOnUncoveredSource` setting.

== Duplicate-source warning

* A file listed in more than one category (or twice in one, via overlapping directory entries) is
  flagged — Dialog would compile it twice, and because order matters that is rarely harmless.
* Toggle with the `dialog-ide.warnOnDuplicateSource` setting.

== Pointing at a specific toolchain (binDir)

* Add a `binDir` field with a directory that contains `dgdebug` / `dialogc` / `aambundle`:
+
[source,json]
----
{
  "name": "my-project",
  "binDir": "/opt/dialog/bin",
  "sources": { "main": ["src"] }
}
----
* Relative paths resolve against the project root; absolute paths are used as-is.
* `binDir` wins over the extension's bundled toolchain *and* anything on `PATH`. Use it for a
  locally built `dgdebug`, or on a platform the extension does not bundle for.
